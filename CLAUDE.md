# Seminarly — Project Guide

The open-source core of **Seminarly**, a local-first macOS app (Swift 6 / SwiftUI) that records meeting audio, transcribes it on-device with WhisperKit, identifies speakers with FluidAudio neural diarization, and generates structured notes via the user's chosen LLM provider (Claude, OpenAI, Gemini, and others). Licensed under **AGPL-3.0**.

This repository is the **source of truth** for the app, CLI, and skill — develop them here.

## Build & Run

```bash
xcodegen generate            # regenerate Seminarly.xcodeproj from project.yml
xcodebuild -project Seminarly.xcodeproj -scheme Seminarly -destination 'platform=macOS' build
open Seminarly.xcodeproj      # or open in Xcode
```

## Test (run before committing)

```bash
xcodegen generate && xcodebuild test -project Seminarly.xcodeproj -scheme SeminarlyTests -destination 'platform=macOS'
```

300+ unit tests live in `Tests/`. CI also runs on every push/PR.

## Releasing

Distributable builds are **notarized DMGs** produced by `scripts/package-app.sh`: archive → Developer-ID sign (hardened runtime) → LZMA-compressed `dmgbuild` installer window → notarize → staple → verify. By default it creates `Seminarly-AppleSilicon.dmg`, `Seminarly-Intel.dmg`, and the universal `Seminarly.dmg` in a fresh directory under `build/packages/`. Publish all three together with the generated signed appcasts, referenced deltas, and pinned ChatGPT component archives: older clients still require `Seminarly.dmg`. Use `--arch arm64|x86_64|universal` to validate one variant. Existing packages are never overwritten. See [packaging details](docs/packaging.md).

- **Bundled CLI** — the archive also embeds + signs the self-contained `seminarly-cli` into `Contents/Helpers/` (a copy-files dependency of the app target), so it is notarized for free. Users install it onto their PATH with one click (Settings → Seminarly CLI and Skills, or the empty-state offer); see [`docs/agent-access.md`](docs/agent-access.md).

- **ChatGPT connection component** — the base app contains a sealed manifest and license notices, not a heavy runtime. First sign-in downloads the pinned native, Developer ID-signed/notarized component into the app's private cache. `scripts/package-app.sh --runtime-only` prepares new components; review and update `Sources/Resources/ChatGPTRuntime.json` before building the app. Never change already-published pins. Keep protocol smoke tests in sync; see [`docs/chatgpt-plan.md`](docs/chatgpt-plan.md).

- **Sparkle updates** — native installers get signed per-architecture feeds and delta updates, with full-DMG fallback. The private Ed25519 signing key remains in Keychain (account `ai.seminarly.updates`); only `SUPublicEDKey` is committed. Publish feeds and all referenced assets together. Preserve the output's `update-history`, pass it as `SPARKLE_PREVIOUS_DIR` next time, and always increment the build number. See [`docs/packaging.md`](docs/packaging.md).

- **Signing identity** — bring your own `Developer ID Application` certificate. The script uses `$DEVELOPMENT_TEAM` if set, otherwise auto-detects the team from your cert; nothing is hardcoded.
- **Notarization** — reads an App Store Connect API key from `~/.asc` (the `asc` CLI store) or the `NOTARY_KEY` / `NOTARY_KEY_ID` / `NOTARY_ISSUER` env vars. (A keychain `notarytool` profile also works, but fails from non-interactive shells.)
- Icon and DMG-background assets are generated by `scripts/make-icon.swift` and `scripts/make-dmg-bg.swift`.

## Conventions

- **Never edit `Seminarly.xcodeproj` directly** — edit `project.yml`, then run `xcodegen generate`.
- **Swift 6 strict concurrency** — use `@MainActor`, `Sendable`, and locks for `@unchecked Sendable`.
- Sources live in `Sources/`; CLI in `CLI/` + `Sources/CLI/`; tests in `Tests/`; the agent skill in `.agents/skills/`.
- The bundle identifier, logger subsystem, and Keychain service all use the `ai.seminarly` prefix — don't hardcode another.
- API keys are stored in the macOS Keychain — never in code or config files.

## Architecture (high level)

Audio capture (Core Audio taps + mic) → WhisperKit transcription (30s streaming chunks) → FluidAudio neural diarization → note structuring via a pluggable `LLMProvider` (Anthropic / OpenAI-compatible / Gemini) → SwiftData storage. See [`docs/`](docs/) for full architecture, setup, and testing notes.
